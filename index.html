Amazon Revenue Analytics

Where does revenue concentrate, what’s at risk next quarter, and where should the category budget go? A four-layer BI framework over 5,026 U.S. Amazon households, 2018–2022 — about 1.85M transactions.

  • Top 10% of households drive 35.9% of GMV (Gini 0.528) — and the gap is ~95% purchase frequency, not basket size.
  • Mid-spend deciles 6–9 hold 64% of revenue-at-risk on just 14% of GMV — retention budgets usually aim at the wrong tier.
  • Every headline number ships with a bootstrap 95% CI; every aggregate is cross-checked byte-for-byte between SQL and Python.

Marketplace Revenue Risk — Olist

Revenue stability, concentration, and cash-flow timing across 99K+ transactions on a Brazilian marketplace, quantified with industry-standard measures.

  • Top 10% of customers drive 38% of revenue — Gini 0.475, HHI 0.18, CV 0.42.
  • São Paulo alone drives 37% of revenue, and ~64% of payments are installment-based (avg 4.12) — a long working-capital cycle.

Python · Claude API · SQLite

Text-to-SQL Agent

Ask a question in plain English; the agent writes the SQL, executes it against a read-only database, and fixes its own errors. Built to learn how AI agents actually work — then tested like a BI tool, not a demo.

  • 10/10 on a clean benchmark (simple counts up to 4-table joins) and 8/8 correct SQL on an adversarial set — synonym traps, temporal filters, NULLs, ambiguous metrics — all against independently computed ground truth.
  • The adversarial set exposed a confident-guessing failure mode: on vague questions the agent silently picks one interpretation instead of flagging it — the exact risk that matters for self-serve BI.
  • A second-pass self-check reviews each answer against the SQL and schema, turning silently-wrong answers into flagged ones.
