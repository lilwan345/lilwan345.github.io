Knovus.ai: Making Practice Questions Answerable

Knovus is an AI study platform that turns a student’s course files into lessons and practice questions. My part is the practice questions: figure out if students can actually answer them, fix what’s broken, and prove the fix works.

  • I sampled 90 stored questions across 16 courses and had each one judged by three independent reviews: 53% couldn’t be fully attempted. It wasn’t the AI model’s fault, the format the questions got saved in just had no place for the full question text.
  • I wrote my manager a proposal with two options, and he forwarded it to the founder and the rest of the team. He picked grading each question against its original page in the course file, which I built, so about 2,400 existing questions kept working without being reprocessed. It got merged into the production code on Sep 28, and he later built on it with PowerPoint and Word previews.
  • A page often has several questions on it, so in round two I turned each one into its own card, copied word for word and checked by 9 rules plus a model. On 60 random production questions I got 37 clean cards and 0 serious errors, it caught all 54 mistakes I planted, and it cost about $0.37 in model calls. (It also wrongly rejected 1 of 8 cards that were already fine.) It was merged and turned on by default Oct 22, and the team has reworked it since.
  • My first grader test scored 100% across 120 gradings, which honestly was suspicious, so I reported it as a failed test and made the cases harder. That caught the cheaper grader marking 1 of 20 wrong answers as right, so the one that shipped is the slower grader that solves the problem first: 0 of 20.
  • 18 of my commits are merged into the production branch, across the FastAPI backend and the Next.js frontend, including about 250 tests.

Amazon Revenue Analytics

Where does the revenue come from, what’s at risk next quarter, and where should the category budget go? I answered that in SQL and Python on about 1.85M purchases from 5,026 U.S. Amazon households, 2018–2022.

  • The top 10% of households spend 35.9% of all the money (Gini 0.528), and about 95% of their lead comes from ordering more often, not from bigger orders.
  • The middle-to-lower spenders (deciles 6–9 of 10) hold 64% of next quarter’s revenue-at-risk but only 14% of the spending. So the households worth protecting aren’t the top spenders.
  • Halfway through I found out my raw file had been cut off at a spreadsheet’s 1,048,576-row limit, and 43% of the rows were just gone. I re-ran everything on the full file and added a check that fails loudly if it ever happens again.
  • The drop-off model holds up on households it never saw: AUC 0.90, where 0.5 is a coin flip (trained on shuffled outcomes it gets 0.53). Key results have 95% confidence intervals, and SQL and Python cross-check every total.

Marketplace Revenue Risk: Olist

How steady is a Brazilian marketplace’s revenue, how much of it depends on one region and a few big orders, and how long does the cash take to show up? I looked at 96K+ delivered orders to find out.

  • The top 10% of orders bring in 38% of revenue (Gini 0.475), and São Paulo alone brings in 37%.
  • About 64% of revenue gets paid in installments, 4.12 on average, so the cash shows up well after the sale.
  • Monthly revenue swings a lot (CV 0.42), but a lot of that is just 2017’s fast growth. With the trend taken out the swings are smaller.

Jun – Jul 2026 · Python · Claude API · SQLite · pytest

Text-to-SQL Agent

You ask a question in plain English and the agent writes the SQL, runs it on a read-only database and fixes its own errors. I built it to learn how AI agents actually work, then tested it like a BI tool instead of a demo.

  • 10/10 on normal questions (simple counts up to 4-table joins) and 8/8 correct SQL on trick questions (synonyms, date filters, missing values, vague metrics), all checked against answers I computed myself.
  • The trick questions turned up a confident-guessing failure mode: on a vague question the agent quietly picks one meaning and doesn’t tell you which. That’s exactly the risk that matters when non-analysts ask their own questions.
  • A second check reviews each answer against the SQL that ran, so a quietly wrong answer comes with a warning. 48 automated tests (no API key needed) run on every push.
